# AlexViet — тестовая площадка

Основной сайт по прежнему адресу показывает только «Sorry, сайт переехал».
Он не содержит ссылки на новое приложение и не перенаправляет посетителей.

Личный тестовый вход Константина: `/AlexViet/test/`. Пароль проверяет серверная
функция `test-access`; доступ разрешён только участнику из закрытой таблицы
`app_private.test_access`, независимо от роли игрока в основном приложении.
Пароль в репозитории не хранится. После входа сохраняется и обновляется сессия
Supabase Auth с отдельным ключом `alexviet.tester.auth.v1`.

Тестовый прогресс хранится локально в пространстве `alexViet.test.*`.
Тестовое приложение не отправляет попытки или результаты в рейтинги VietSveta.
Учебные материалы основного сайта уже находятся в репозитории VietSveta:
его сборка не скачивает файлы из AlexViet.

## Разработка

```sh
npm ci
npm run dev
npm run build
npm test
```

В разработке открывать `/AlexViet/test/`. Сборка содержит два независимых HTML
входа: `dist/index.html` (сообщение о переезде) и `dist/test/index.html`
(вход и приложение). Медиа остаются в `public` для тестирования.

Новые эксперименты выполняются здесь. Перенос в VietSveta — отдельное действие
после одобрения, без изменения пользовательской статистики.

Схема тестового доступа: `supabase/test_access.sql`, серверная функция:
`supabase/functions/test-access/index.ts`. Клиент никогда не получает служебный
ключ Supabase или внутренний пароль Auth. Таблица доступа закрыта RLS и не
доступна клиентским ролям; после пяти неверных паролей действует блокировка
на 15 минут. Пароль тестера задаётся отдельно через серверное управление.
